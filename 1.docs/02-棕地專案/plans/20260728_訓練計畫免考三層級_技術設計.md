## 1. 目的

1. 讓訓練計畫可在**受課指派之外**，另以 **角色／單位／個人** 三層級設定「免考」。
2. 考試中心、成績／待考統計、個人應考計畫數等，一律以「實際需考」口徑計算，避免應考與免考混用。
3. 報到口徑分離：**僅預設超管角色免報到**；其餘免考者仍須報到並計入應到。
4. 前端以「主編輯 modal → 開課單位旁按鈕 → 免考設定子 modal」維護，避免主畫面再擠高。

## 4. 名詞解釋

| 名詞 | 定義 |
|------|------|
| **受課對象／應考母集合** | 既有：`target_departments` 全員 ∪ `target_users`；兩者皆空＝全公司（且實務統計通常再濾 `status=active`、`is_trainee=true`） |
| **免考對象** | 本計畫設定之免考角色 ∪ 免考單位 ∪ 免考個人（OR） |
| **實際需考** | 應考母集合 − 免考對象 |
| **預設超管** | `SUPER_ADMIN_ROLE_NAMES`：`Admin`、`System Admin`、`系統管理`、`系統管理者`（見 `backend/app/constants/auth.py`） |
| **免報到** | 僅**預設超管**；其餘免考者**仍須報到** |
| **受課 UI** | 開課單位、受課單位、個人受課對象；**不得**混入或扣除免考顯示 |
| **免考設定子 modal** | 由主「編輯訓練計畫」modal、開課單位旁按鈕開啟之獨立設定畫面 |

## 5. 作業內容

### 5.1 業務規則（定案）

```text
assigned  = 受課單位全員 ∪ 個人受課對象（皆空則全公司；統計再濾在職受訓者）
exempt    = 免考角色成員 ∪ 免考單位成員 ∪ 免考個人
need_exam = assigned − exempt

need_checkin =
  assigned − { u ∈ assigned | u.role ∈ SUPER_ADMIN_ROLE_NAMES }

# 對單一使用者：
requires_exam(u, plan)      = in_targets(u, plan) AND NOT is_exam_exempt(u, plan)
requires_checkin(u, plan)   = in_targets(u, plan) AND NOT is_super_admin_role(u.role.name)
# 注意：一般免考者 requires_exam=false，但 requires_checkin=true（若在 assigned 內）
```

| # | 規則 | 定案 |
|---|------|------|
| R1 | 免考三層級 | 角色／單位／個人，OR，命中即免考 |
| R2 | 排除優先 | 即使在 `target_users`，只要命中免考 → 不用考 |
| R3 | 資料分離 | `target_*` 與 `exam_exempt_*` 分開儲存，禁止互寫 |
| R4 | 超管預設 | 新建計畫時，免考角色**實體寫入**預設超管角色；UI **不可取消**（鎖定） |
| R5 | 報到 | **僅**預設超管免報到；其餘免考者仍須報到、仍計應到 |
| R6 | 受課 UI 隔離 | 開課／受課單位／個人受課對象**不顯示、不扣除**免考 |
| R7 | UI 入口 | 開課單位旁「免考設定」→ 子 modal；主 modal 僅摘要 |

### 5.2 資料模型

#### 5.2.1 新表（建議命名）

```sql
-- 計畫免考角色
CREATE TABLE plan_exam_exempt_roles (
  plan_id INTEGER NOT NULL REFERENCES training_plans(id),
  role_id INTEGER NOT NULL REFERENCES roles(id),
  PRIMARY KEY (plan_id, role_id)
);

-- 計畫免考單位
CREATE TABLE plan_exam_exempt_departments (
  plan_id INTEGER NOT NULL REFERENCES training_plans(id),
  dept_id INTEGER NOT NULL REFERENCES departments(id),
  PRIMARY KEY (plan_id, dept_id)
);

-- 計畫免考個人
CREATE TABLE plan_exam_exempt_users (
  plan_id INTEGER NOT NULL REFERENCES training_plans(id),
  emp_id  VARCHAR NOT NULL REFERENCES users(emp_id),
  PRIMARY KEY (plan_id, emp_id)
);
```

#### 5.2.2 ORM／Schema 對應

| 層 | 欄位 |
|----|------|
| `TrainingPlan` relationships | `exam_exempt_roles`、`exam_exempt_departments`、`exam_exempt_users` |
| Request（create／update） | `exam_exempt_role_ids: list[int]`、`exam_exempt_dept_ids: list[int]`、`exam_exempt_user_ids: list[str]` |
| Response | 對應詳情列表（含 name／dept_name 等，便於前端摘要） |

#### 5.2.3 新建／更新寫入規則

1. **Create**：若客戶端未傳 `exam_exempt_role_ids`，後端**強制**補上所有存在於 DB 且名稱 ∈ `SUPER_ADMIN_ROLE_NAMES` 的 `role_id`。
2. **Update**：合併寫入時，後端**一律確保**超管角色仍在 `exam_exempt_roles`（即使前端漏傳或試圖移除）。
3. 免考單位／個人：可空；儲存前濾 `active` 使用者（個人）與合法 dept／role id。

### 5.3 後端解析 Helper（建議落點）

建議擴充 `backend/app/services/attendance_checkin.py`（或新建 `exam_exemption.py`，由 attendance／exam_center／training／report 共用）：

| 函式 | 行為 |
|------|------|
| `user_in_plan_targets(user, plan)` | **維持現況**（已存在） |
| `user_is_exam_exempt(user, plan)` | 角色 id ∈ exempt_roles **或** dept ∈ exempt_depts **或** emp ∈ exempt_users |
| `user_requires_exam(user, plan)` | `in_targets AND NOT exempt` |
| `user_requires_checkin(user, plan)` | `in_targets AND NOT is_super_admin_role(role.name)` |
| `resolve_assigned_emp_ids(plan, db)` | 應考母集合 emp_id 集合（active＋trainee） |
| `resolve_exam_required_emp_ids(plan, db)` | assigned − exempt |
| `resolve_checkin_expected_emp_ids(plan, db)` | assigned − super_admins |

### 5.4 API 行為對齊

| 端點／模組 | 行為 |
|------------|------|
| `POST/PUT /training/plans` | 讀寫免考欄位；強制保留超管免考角色 |
| `GET /training/plans*` | 回傳免考詳情，供摘要／子 modal |
| `GET .../attendance/stats`、`calculate-expected-attendance` | **應到**＝`resolve_checkin_expected_emp_ids`（含一般免考者，不含超管） |
| 報到 checkin | 非受課 → 拒絕；**超管**可跳過或直接視為不需報到（不寫入、不計應到）；一般免考者**允許並要求**報到後才能開考？→ **否**：免考者不开考，但仍應能報到寫入 |
| `GET /exam/my_exams` | 僅 `requires_exam` 為 true 之計畫列入「待考／可開考」；可選回傳 `is_exam_exempt` 供「已列入但免考」標示（產品預設：**可不顯示免考計畫**，或顯示「免考」徽章——**PLAN 採：不列入可開考列表**） |
| `start_exam`／`submit_exam` | `requires_exam` 否則 403；`requires_checkin` 者仍須有 `attendance_records` |
| 個人分析／應考計畫數／待考 KPI | 分母與待考改用 `exam_required` |

### 5.5 前端設計

#### 5.5.1 主 modal（`TrainingPlanManager`）

- 開課單位 `<select>` **右側**放按鈕「免考設定」。
- 按鈕旁或下方顯示摘要：`角色 N · 單位 N · 個人 N`；可選顯示「免考後需考 M 人」（M 依目前表單受課＋免考前端估算，儲存後以後端為準）。
- **受課單位／個人受課對象**區塊：維持現況，**不**過濾免考、**不**標免考 badge。

#### 5.5.2 子 modal「免考設定」

- 開啟條件：主 modal 已開；`z-index` 高於主 modal（可比照「新增個人對象」`z-[70]`）。
- 內容三區：
  - 免考角色：checkbox；超管角色列顯示鎖定、不可取消。
  - 免考單位：可比照受課單位 checkbox。
  - 免考個人：搜尋加入／移除。
- 「完成」僅關閉子 modal，資料留在父表單 state；隨主表單「儲存變更」一併送 API。
- 檢視模式（非開課單位）：子 modal 唯讀。

### 5.6 與「超管試考模式」關係

| | 本規格（免考三層級） | 20260723 試考模式 |
|--|---------------------|-------------------|
| 對象 | 計畫內受課＋免考設定 | 管理帳號瀏覽／試考 |
| 考試 | 免考者不開正式考 | 可試考但不落庫 |
| 報到 | 超管免報到；其餘免考要報到 | 試考跳過報到 |
| 資料 | 寫入 exempt 關聯表 | 不寫 exam／attendance |

實作時兩邊 helper 勿互相覆蓋；`is_trainee=false` 之超管通常本就不在 trainee 應到名單，本規格仍以**角色名**強制免考／免報到，避免日後 `is_trainee` 誤設導致破口。

### 5.7 測試要點（規格級）

1. 新建計畫 → DB 必有超管 `role_id` 於 `plan_exam_exempt_roles`。
2. Update 試圖移除超管角色 → 後端仍保留。
3. 受課單位 A＋免考角色 R → A∩R 不用考，仍須報到（非超管）。
4. 個人受課＋個人免考 → 不用考，須報到。
5. 超管在母集合 → 不用考、不計應到、報到 API 不要求／不虛增。
6. `my_exams` 不含免考者計畫；`start_exam` 對免考者 403。
7. 應到人數含一般免考、不含超管；待考人數不含全部免考。

## 7. 使用表單（欄位說明）

### 7.1 訓練計畫 — 免考設定（子 modal）

| 欄位 | 型別 | 必填 | 說明 |
|------|------|------|------|
| 免考角色 | 多選 role_id | 否（但超管必存在） | 屬該角色者本計畫免考；超管列鎖定不可取消 |

| 免考個人 | 多選 emp_id | 否 | 指定員工本計畫免考；可跨單位 |

### 7.2 API Payload（建議）

| 欄位 | 型別 | 說明 |

| `exam_exempt_role_ids` | `int[]` | 免考角色；後端會 union 超管 |
| `exam_exempt_dept_ids` | `int[]` | 免考單位 |
| `exam_exempt_user_ids` | `string[]` | 免考員工編號 |

### 7.3 主 modal 摘要（顯示用，非獨立存檔）

| 顯示項 | 來源 |
|--------|------|
| 免考角色 N | `exam_exempt_role_ids.length` |
| 免考單位 N | `exam_exempt_dept_ids.length` |
| 免考個人 N | `exam_exempt_user_ids.length` |
