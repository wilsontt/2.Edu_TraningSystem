**文件類型**：棕地實作計劃  
**建立日期**：2026-07-28  
**狀態**：📋 **待實作**（規格已對齊；核准後開 TASKS／實作）  
**技術設計**：[20260728_訓練計畫免考三層級_技術設計.md](20260728_訓練計畫免考三層級_技術設計.md)  
**相關**：[20260723_超管考試中心試考模式_PLAN.md](20260723_超管考試中心試考模式_PLAN.md)（試考模式另案；本 PLAN 不實作試考）

> **背景**：訓練計畫受課對象僅有「單位 ∪ 個人」。產品需要另以**角色／單位／個人**設定免考；受課 UI 不混入免考；超管預設且鎖定免考；**僅超管免報到**，其餘免考者仍須報到。

---

## 1. 目的

1. 新增計畫層級免考設定（角色／單位／個人），與 `target_*` 分離。
2. 考試中心與成績／待考口徑改吃「實際需考」。
3. 報到應到口徑：含一般免考者、排除預設超管。
4. 前端：開課單位旁「免考設定」子 modal＋主畫面摘要。

| # | 決策 |

### 5.2 Phase 明細

#### P1 — 資料模型

- [ ] Migration 建立 `plan_exam_exempt_roles`／`_departments`／`_users`
- [ ] ORM relationships；既有計畫**不**強制 backfill（下次 update／或另寫一次性腳本可選：為既有計畫補超管角色——**建議 migration 後執行 backfill 超管角色到所有現有計畫**，避免舊計畫超管仍被要求考試）
- [ ] Schemas：`exam_exempt_role_ids` 等

**建議**：migration 結尾對所有 `training_plans` INSERT 超管 `role_id`（若角色存在），與「新建預設」一致。

#### P2 — Helper

- [ ] `user_is_exam_exempt`／`user_requires_exam`／`user_requires_checkin`
- [ ] `resolve_*_emp_ids` 三函式
- [ ] 單元測試先寫後實作（TDD）

#### P3 — 訓練計畫 API

- [ ] create／update 寫入三關聯；強制 union 超管 role_ids
- [ ] GET 回傳免考詳情
- [ ] 拒絕無效 role／dept／emp（404／400）

#### P4 — 考試中心

- [ ] `_count_assigned_plans_for_user`／`my_exams` 改為需考口徑（或新增平行計數並讓分析 API 使用需考）
- [ ] `start_exam`／`submit_exam`：`requires_exam` 否則 403
- [ ] 報到檢查：僅 `requires_checkin` 時呼叫 `_require_attendance_record`

#### P5 — 報到

- [ ] `attendance/stats`、`calculate-expected-attendance`：應到＝checkin expected
- [ ] checkin：超管若誤掃 → `skipped` 或不建立 record（避免虛增）；一般免考者成功報到
- [ ] 未報到名單：含一般免考未報到者；不含超管

#### P6 — 成績／報表

- [ ] 個人「總計畫數／應考計畫」改需考
- [ ] 待考 KPI 排除免考
- [ ] 迴歸：部門成績、授權重考不受影響（仍依 ExamRecord）

#### P7 — 前端

- [ ] 表單 state：`exam_exempt_role_ids`／`dept_ids`／`user_ids`
- [ ] 開課單位旁按鈕＋子 modal（鎖定超管角色）
- [ ] 主畫面摘要；受課區塊零免考 UI
- [ ] 載入計畫時填入免考；儲存一併送出
- [ ] 檢視模式唯讀
